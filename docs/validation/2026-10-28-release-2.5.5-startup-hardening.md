## Execution-context audit and repairs

| Path | Execution and failure handling |
| --- | --- |
| Android pending-flight panel, including resume after device credentials | `awaitingMapStorage` switches to `Dispatchers.IO` before storage access or recovery. Failure returns panel state, stops polling, and requires explicit retry. Coroutine cancellation propagates. |
| Android incident/flight review ordering and clue ownership | Full history and geometry work is prepared on IO, outside Compose rendering. |
| Android stream ViewModel construction | The calibrated release benchmark exposed a first-read wait in legacy anomaly-preference cleanup. Cleanup now runs within `SettingsStartup` on its settings worker. The ViewModel creates only bounded in-memory session defaults. |
| Android recording shutdown | Staging-directory preparation is inside `syncAll`'s exception boundary on the existing native-control worker. A storage failure is logged rather than escaping teardown. |
| Android document verification | Non-truncating `rw` descriptor reads the retained bytes. A provider denying that descriptor fails safely; checksum verification is never bypassed. |
| Apple flight journal initialization, geometry and mutations | A background actor owns journal state. A serial `OperationalWorkQueue` handles reads, decoding, encoding and atomic writes. MainActor receives committed snapshots. Missing data is empty; corrupt or unavailable data blocks mutations and exposes a retryable error. |
| Apple review panel | A separate actor prepares full-history ownership, relevance, proximity, ordering and reminders from immutable snapshots. A cancelled/stale view task cannot publish its result. |
| Apple clue capture, waypoint binding and deferred publication | Track-point conversion, nearest-waypoint matching and publication geometry expansion run on detached workers with immutable inputs; cancellation and selection/configuration checks precede UI publication. |
| Apple clue startup/index reads and destination resolution | Serial disk worker decodes complete indexes and journal decisions. Unreadable indexes are preserved and block writes; unavailable decisions pause publication. Metadata is not silently removed because its image is unavailable. |
| Apple clue archive and deferred-flight matching | Ownership and geometry matching run on workers. Revision checks reject outdated prepared binding snapshots; durable consent/destination writes precede starting upload. |
| Apple Core Location startup | A separate actor performs location-service and heading-availability queries. MainActor creates/updates the location manager only after the result, with cancellation and session-generation guards. Runtime warning summaries fail the startup gate for detected blocking Main-thread work. |
| Apple launch acceptance | Saved-settings load and acceptance encoding/persistence run on workers. MainActor enables the app only after successful persistence. |

The Android crash involved its document-provider adapter; Apple does not use that
adapter. This excludes that exact implementation path on iOS. It does not prove
that every possible startup crash, storage failure or UI stall has been eliminated.
The audit covers these startup/recovery/review paths, not every app feature.

## Release qualification

`app:releaseVerification` now executes `emulatorRecoveryQualification`, rather than
only compiling its instrumentation APK. The driver starts its own read-only AVD
instance and validates `ranchu`; every adb command names its owned emulator. It
never selects a connected physical device. It installs in place and invokes
instrumentation directly, without a managed connected-test runner.

The Gradle task orders measurements after scheduled compilation, compression and
host/native tests so those jobs do not contaminate emulator frame timings.

The profileable, minified benchmark variant inherits Release optimization and adds
only a qualification-only StrictMode provider. The provider records disk/network
violations from before application initialization. Host R8 retrace restores class
and inlined-call identities before attributing I/O to the first non-I/O caller.
A deliberate benchmark-only read calibrates the actual detector on each process.
Framework/library reads are retained in the log and distinguished from direct
app-owned I/O. The provider is absent from distributed Release and normal Debug.

Macrobenchmark records three iterations each of cold launch, foreground return and
warning-screen steady touch scrolling after a warmup, with screenshots captured
outside the measured interval (this runtime does not expose
the wrapped Compose virtual nodes to UIAutomator). Emulator thresholds are regression smoke budgets:
5 seconds to initial display, 500 ms cold-initial frame CPU p95, 100 ms scrolling
frame CPU p95. Foreground return need not render a new frame. These thresholds are
not hardware smoothness claims. Real-device profiling remains useful for tighter
budgets and manufacturer/provider differences.

The Android recovery suite includes the real OS ExternalStorageProvider with a
multi-megabyte GPS-bearing JPEG, interrupted publication after rename, exact-byte
and EXIF retention, revoked-access failure, a stalled-provider Main heartbeat,
and StrictMode calibration. Existing provider simulation also reproduces the
original transformed-media failure. Host faults cover provider quota exhaustion,
corrupt-journal quarantine, interrupted mutation boundaries and cancellation.

Apple's release check runs Swift tests plus `run_apple_startup_qualification.py`.
The latter creates a disposable Simulator, builds the Release configuration,
seeds an unreadable flight journal, accepts warnings only within that fixture,
checks visible error/retry across initial launch and foreground return, measures repeated
launch to either recovery UI or the normal protected-access gate if browser cookies
were retained, and verifies the journal bytes are unchanged. Core tests verify all six
journal mutations reject unreadable history, repaired storage can be retried,
cancelled work cannot commit, corrupt clue indexes survive, and the actual journal
and review actors execute off Main with 20,000 track points.

## Reproduction

Android: `./gradlew :app:releaseVerification` (requires the qualification AVD,
default `R2C_Units_Qualification`, override `-PqualificationAvd=NAME`). For the
large Kotlin compilation on this host use `--max-workers=2`,
`-Dorg.gradle.jvmargs='-Xmx4g -Dfile.encoding=UTF-8'` and
`-Pkotlin.daemon.jvmargs=-Xmx6g`.

Apple: `apple/release-check.sh --skip-native-rebuild --archive-path PATH` verifies
existing native XCFrameworks and runs all remaining release checks. Omit the skip
flag when native sources change. Standalone runtime qualification:
`python3 tools/qualification/run_apple_startup_qualification.py --output PATH`.

Runtime reports, traces, logs, final artifact checksums and completion results are
recorded below after qualification. Store delivery is a separate step; the S11
Play-installed app requires a Play-signed update because local and Play signing
certificates differ.
